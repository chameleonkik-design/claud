# 🎹 Chord Progression Studio

コード進行を組み立てて、その場で試聴して、**MP3としてダウンロード**できるWebアプリです。

すべてブラウザ内で完結します。サーバーへの音声アップロードは一切なく、音源の合成から
MP3のエンコードまで端末上で行われます。

---

## できること

| | |
|---|---|
| **進行を作る** | キー・スケールを選ぶとダイアトニックコードが自動で並ぶ。クリックで追加、拍数や転回も指定可能 |
| **試聴する** | ▶ボタンで即再生。ループ再生中は今鳴っているコードがハイライトされ、鍵盤に構成音が光る |
| **MP3で書き出す** | 128 / 192 / 256 / 320 kbps を選んでダウンロード。WAV（16bit PCM）にも対応 |
| **共有する** | 進行をURLに埋め込めるので、リンクを送るだけで相手の画面に同じ進行が開く |

### 音楽的な中身

- **8つのスケール** — メジャー / ナチュラルマイナー / ハーモニックマイナー / メロディックマイナー / ドリアン / フリジアン / リディアン / ミクソリディアン
- **30種類以上のコード** — 三和音から 6th, 7th, 9th, 11th, 13th, sus, add, 裏コードまで
- **借用コード** — 各度数へのセカンダリードミナント（V7/ii など）、同主調からの借用、トライトーンサブスティチュート
- **14の定番進行プリセット** — 王道進行、小室進行、小悪魔進行、カノン進行、4536、6451、12小節ブルース、シティポップ、アンダルシア終止など
- **7つの音色** — ピアノ / エレピ / パッド / オルガン / ギター（撥弦）/ ストリングス / オルゴール
- **11の弾き方** — 白玉、4分打ち、8分刻み、アルペジオ（上昇・下降・往復・16分）、アルベルティ・バス、ストラム、ボサノヴァ、バラード
- **ベース6種 + ドラム5種** — オクターブ、ルート＋5度、8ビート、4つ打ち、ボサノヴァ など
- **なめらかなボイシング** — 直前の和音にいちばん近い転回形を自動で選び、和音が飛び回らないようにする

## 使い方

```bash
npm install
npm run dev      # 開発サーバー（http://localhost:5173）
```

```bash
npm run build         # 型チェック + 本番ビルド → dist/
npm run build:single  # 1枚のHTMLにまとめる → dist-single/
npm run preview       # ビルド結果を確認
npm test              # テスト（音楽理論・アレンジ・エンコーダ）
```

### 置き場所

**GitHub Pages への自動デプロイ**を `.github/workflows/deploy.yml` に用意してあります。
`main` に push するとテスト → ビルド → 公開まで走ります。初回だけ、リポジトリの
**Settings → Pages → Source を「GitHub Actions」に切り替える**操作が必要です。

> **iPhone で使う場合は、埋め込みではなく単独のタブで開いてください。**
> iframe の中では Permissions Policy によって共有シート（Web Share API）が
> 使えず、iOS はファイル保存の手段が無くなります。詳しくは下の「iOSでの保存」を参照。

`vite.config.ts` で `base: "./"` にしてあるので、`dist/` をそのまま静的ホスティング
（GitHub Pages のサブディレクトリ配信など）に置けます。

`npm run build:single` は CSS と JS をインライン化した
`dist-single/chord-progression-studio.html` を作ります。**外部ファイルを一切
読み込まない1枚のHTML**なので、ダブルクリックでそのままブラウザで開けますし、
ファイルを1つ配るだけで誰にでも渡せます。

## 設計

### 「聴こえたとおりに書き出される」仕組み

試聴とMP3書き出しで音が変わらないよう、**スケジューラを1本に統一**しています。

```
Song（曲データ）
  └─ buildArrangement()      … コード進行 → 音符イベント列（拍単位）
       └─ scheduleArrangement(ctx, …)
            ├─ ctx = AudioContext         → 試聴
            └─ ctx = OfflineAudioContext  → MP3 / WAV 書き出し
```

`scheduleArrangement()` は `BaseAudioContext` を受け取るだけで、リアルタイムか
オフラインかを気にしません。パターン生成にも乱数を使っていない（ノイズ波形すら
固定シードの擬似乱数）ので、同じ設定なら常に同じ波形になります。

### 書き出しの流れ

1. `OfflineAudioContext(2ch, 44.1kHz)` で曲を丸ごとレンダリング
2. Float32 の PCM を Int16 に変換（クリップ処理つき）
3. [lamejs](https://github.com/zhuker/lamejs) で MP3 フレーム（1152サンプル）単位にエンコード
4. Blob を作って `<a download>` で保存

エンコードは 64 フレームごとに制御をイベントループへ返すので、進捗バーが動き、
UIが固まりません。

### iOSでの保存

iOS Safari は blob URL に対する `<a download>` を**黙って無視する**ので、
そのままではダウンロードが「押しても何も起きない」状態になります。
そこで iOS では保存経路を段階的に切り替えています。

1. **共有シート** — `navigator.share({ files })` に File を渡し、「"ファイル"に保存」してもらう
2. **別タブで開く** — 共有が拒否されたら `window.open(blobURL)`。iOS はプレイヤーを開くので、
   その画面の共有ボタンから保存できる
3. **案内を出す** — どちらも塞がれていたら、黙って失敗させず理由と対処を表示する

Web Share API は**ユーザー操作の直後**しか呼べません。レンダリングとエンコードに
数秒かかるとその権利が切れるため、iOS では書き出し完了後に「ファイルに保存」ボタンを
出す**2段階**にしています。

なお `web-share` は Permissions Policy の対象で、**iframe にはデフォルトで許可されません**。
埋め込み表示では 1 も 2 も塞がれるため、iPhone では単独のタブで開く必要があります。

### 音量設計

マスターチェーンは `各パートのバス → (dry + リバーブ) → グルーコンプ → リミッター → 音量`
という構成です。バスのレベルは、いちばん音が厚くなる組み合わせ（音色・弾き方・
ドラム・リバーブ全開）でも 0 dBFS に当たらない値に決めてあり、さらに保険として
リミッターを置いています。全27パターンの組み合わせで実測し、最大ピークは -0.3 dBFS、
クリップしたサンプルは0でした。

### コード進行の持ち方

進行は絶対音ではなく **キーの主音からの半音数（offset）** で保持しています。
そのためキーを変えるだけで全体が自動的に移調され、プリセットもキーに依存しません。

```ts
// Fmaj7 in C major は「主音から5半音上の maj7」として保存される
{ offset: 5, quality: "maj7", beats: 4 }
```

## ファイル構成

```
src/
├─ music/            音楽理論（オーディオに依存しない純粋なロジック）
│  ├─ notes.ts         音名・ピッチクラス・MIDI番号・周波数
│  ├─ chords.ts        コードの種類定義、構成音 ↔ コード名
│  ├─ scales.ts        スケール、ダイアトニックコード、借用コードの導出
│  ├─ voicing.ts       和音 → MIDIノート（ボイスリーディング）
│  ├─ patterns.ts      リズム / アルペジオパターン → 音符イベント
│  ├─ presets.ts       定番進行プリセット
│  └─ song.ts          曲データのモデルとアレンジの組み立て
├─ audio/            Web Audio 層
│  ├─ instruments.ts   シンセ音源（サンプル不要）とドラム
│  ├─ render.ts        マスターチェーンとスケジューラ（試聴/書き出し共通）
│  ├─ player.ts        試聴コントローラ（ループの先読みスケジューリング）
│  └─ export.ts        オフラインレンダリング、MP3 / WAV エンコード
├─ components/       UI 部品
├─ state.ts          初期値・localStorage保存・共有リンクの符号化と検証
└─ App.tsx           画面全体

tests/
├─ theory.test.ts       音名、コード、スケール導出、ボイシング、プリセット
├─ arrangement.test.ts  パターン展開、アレンジ、保存データの正規化
└─ export.test.ts       WAVヘッダ、MP3フレーム、進捗、ファイル名
```

## 支援リンク（投げ銭）を出す

`src/support.ts` の `url` に支援ページのURLを入れると、画面下部に支援カードが出ます。
**空のままなら何も表示されません**ので、準備ができるまで放置して構いません。

```ts
export const SUPPORT: SupportConfig = {
  url: "https://ko-fi.com/yourname",   // ← ここだけ変えればよい
  label: "☕ 開発を応援する",
  message: "このアプリは無料で、広告もありません。気に入ったら開発の支援をお願いします。",
};
```

使えるサービスの例（どれもアカウントを作ってリンクを貼るだけ）:

| サービス | 特徴 |
|---|---|
| [Ko-fi](https://ko-fi.com/) | 手数料が安い。買い切り・継続どちらも可 |
| [Buy Me a Coffee](https://buymeacoffee.com/) | 日本語話者にも知名度がある |
| [GitHub Sponsors](https://github.com/sponsors) | 開発者向け。GitHubアカウントで完結 |
| Stripe Payment Link | 自由度が高い。ダッシュボードでリンクを発行 |

URL は `https://` のみ受け付けます。それ以外（`http:` や `javascript:` など）は
無効な設定として扱い、カード自体を表示しません。設定ミスがそのまま危険なリンクに
ならないようにするためです。

### 有料化する場合の注意

現状このアプリは**すべてブラウザ内で動く静的サイト**なので、「支払った人だけ使える」
という制限はかけられません（JavaScript は誰でも読めて書き換えられるため）。
機能制限をともなう課金をしたい場合は、価値のある処理をサーバー側に置く必要があります。

また、MP3 エンコードに使っている lamejs は **LGPL-3.0** です。ソースを公開したまま
配布する分には問題ありませんが、クローズドにして販売する場合はライセンス条件の
確認が必要です（`MediaRecorder` に統一すればこの制約は外せます）。

## 動作環境

Web Audio API と `OfflineAudioContext` に対応したモダンブラウザ
（Chrome / Edge / Firefox / Safari）。iOS Safari では最初の再生ボタンのタップで
音声が有効になります。
